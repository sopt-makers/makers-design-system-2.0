# 디자인 토큰이란?

디자인 토큰이란 디자인 의사결정이 담긴 변수를 코드화한 것으로, 디자이너와 개발자가 동일한 기준으로 소통하기 위한 공통 언어입니다.

## 1. 왜 디자인 토큰을 사용하나요?

명확한 기준이 없다면 같은 상황에서도 디자이너와 개발자마다 서로 다른 선택을 할 수 있어요.

![왜 디자인 토큰을 사용하나요](/images/img_designtoken_01.png)

예를 들어 동일한 체크박스 컴포넌트의 텍스트 색상으로 누군가는 gray900, 누군가는 gray800, 또 다른 누군가는 gray700을 사용할 수 있어요. 각 선택은 개별적으로 합리적일 수 있지만, 이러한 결정이 반복되면 제품 전반의 일관성이 흐려지고 관리 비용이 증가하게 돼요.

MDS는 이러한 문제를 해결하기 위해 토큰 구조를 사용해요. 디자이너와 개발자가 실제 값 대신 역할과 의미를 기준으로 의사결정할 수 있도록 공통된 기준을 제공하며, 이를 통해 일관된 사용자 경험과 효율적인 유지보수를 지원해요.

## 2. 토큰 구조

메이커스 디자인 시스템은 디자인 결정을 일관되게 표현하고 관리하기 위해 토큰 구조를 사용해요. 토큰은 실제 값과 사용 목적 사이에 추상화 계층을 만들어, 디자인 의도와 구현 방식을 분리할 수 있도록 해요.

![토큰 구조](/images/img_designtoken_02.png)

### Raw Value

Raw Value는 디자인 속성을 구성하는 실제 값이에요. 색상, 크기, 간격, 폰트 크기 등 더 이상 분해할 수 없는 기본 단위의 값을 의미해요. Raw Value는 시각적 표현의 기반이 되지만, 값 자체에는 사용 목적이나 맥락이 포함되어 있지 않아요.

### Base token

Base Token은 Raw Value를 체계적으로 분류하고 관리하기 위한 토큰이에요. 특정 값에 일관된 이름을 부여함으로써 디자인 시스템 전반에서 동일한 값을 반복적으로 사용할 수 있도록 해요. Base Token은 값 자체를 표현하며, UI에서의 역할이나 의미는 포함하지 않아요.

![Base token 예시](/images/img_designtoken_03.png)


> Base Token은 색상을 관리하기 위한 시스템 내부 레이어예요. 제품 UI에서는 직접 사용하는 것을 권장하지 않아요.

### Semantic Token

Semantic Token은 UI에서의 역할과 의도를 표현하는 토큰이에요. Semantic Token은 특정 값을 직접 의미하지 않고, 디자인 결정을 표현해요. 예를 들어 color.bg.brand.default는 특정 주황색을 의미하는 것이 아니라, '브랜드를 나타내는 기본 배경색'이라는 역할을 의미해요. 이러한 추상화를 통해 실제 값이 변경되더라도 디자인의 의도는 유지할 수 있어요.

![Semantic token 예시](/images/img_designtoken_04.png)


## 3. 사용 원칙

Semantic Token만 직접 참조(사용)가 가능해요. 예외적으로 spacing은 Base token 사용이 가능해요.

<span style={{color: 'white', display: 'block', paddingBottom: '12px'}}>Q. 왜 Semantic token만 사용할 수 있나요?</span>

같은 의도를 가진 스타일을 일관되게 유지할 수 있어요. Base token은 원시 값에 단순 이름만 붙인 것이기 때문에, 값이 변경될 때 어디에 어떤 영향을 미치는지 추적하기 어려워요.

<span style={{color: 'white', display: 'block', paddingBottom: '12px'}}>Q. 왜 Spacing과 Radius만 Base token 사용이 가능한가요?</span>

다양한 해상도 환경에 유연하게 대응해야 하며, 적용되는 맥락과 용처가 매우 광범위해요. 따라서 특정 의미를 부여하기보다는 수치 기반의 시스템을 유지하여 범용성을 확보해야 해요.<div style={{paddingBottom: '100px'}} />
