# Grammar

서비스에서 사용하는 표기법과 문장 부호, 맞춤법, 용어 사용 원칙 등을 정의합니다. 누구나 동일한 기준으로 콘텐츠를 작성할 수 있도록 안내해요.

## 1. 공식 표기

**SOPT**

SOPT는 항상 대문자로 작성해주세요.

| 구분 | 예시 |
| --- | --- |
| NO | sopt, Sopt |
| YES | SOPT |

**SOPT 각 파트**

모든 파트를 순서대로 나열할 때, 기획-디자인-안드로이드-iOS-웹-서버 순서대로 나열합니다.

| 구분 | 명칭 |
| --- | --- |
| YES | 기획, 디자인, 안드로이드, iOS, 웹, 서버 |

**YB, OB, 명예 OB**

활동기수 중 회원 경력을 구분해야할 때 사용해주세요. 단, 명예 OB는 비활동기수지만 활동기수의 특정 이벤트에 참여하는 회원을 말해요.

| 구분 | 예시 |
| --- | --- |
| NO | 뉴비, 신입, 명비 |
| YES | YB, OB, 명예 OB |

**SOPT Makers**

makers는 SOPT에 소속된 조직으로, 조직 명을 써야할 때는 makers 앞에 SOPT를 붙여주세요. 디자인이나 빠른 이해를 돕기 위해 SOPT를 제외한 makers만 작성할 경우에도 makers는 소문자로 작성해요.

| 구분 | 예시 |
| --- | --- |
| NO | MAKERS, 메이커스, 메팀 |
| YES | SOPT makers, makers, 메이커스 팀 |

**기타**

자세한 내용은 SOPT makers 내부 구성원에게 제공되는 UX Writing 가이드라인에서 확인할 수 있어요.

## 2. 문장 부호

**콜론(:), 콤마(,)**

콜론 뒤에 숫자나 기호로 이루어진 값이 올 경우, 띄어쓰지를 하지 않아요. 콜론 뒤에 일반 단어나 문장이 올 경우, 띄어쓰기를 해주세요. 쉼표 뒤에는 모두 띄어쓰기를 해주세요.

| 구분 | 예시 |
| --- | --- |
| NO | 00 : 00, 1 : 1, 담당자:김솜핏, 1,2,3, 기획,디자인,안드로이드,iOS,웹,서버 |
| YES | 00:00, 1:1, 담당자: 김솜핏, 1, 2, 3, 기획, 디자인, 안드로이드, iOS, 웹, 서버 |

**슬래시(/)**

두 개 이상의 단어로 이루어진 정보 블록을 구분할 때는 앞뒤로 띄어쓰기를 하고, 단어끼리 연결할 때는 앞뒤로 띄어쓰기를 하지 않아요.

| 구분 | 예시 |
| --- | --- |
| NO | 날짜 0000.00.00 (토)/00:00-23:59, 로그인 / 회원가입 |
| YES | 날짜 0000.00.00 (토) / 00:00 ~ 23:59, 로그인/회원가입 |

**중간점(·)**

동등한 항목을 간결하게 나열할 때 사용하며, 선택이나 대안의 의미로는 사용하지 않아요. 중간점 앞뒤로는 띄어쓰기를 하지 않아요.

| 구분 | 예시 |
| --- | --- |
| NO | 기획 · 디자인, 로그인 · 회원가입 |
| YES | 기획·디자인, 로그인/회원가입 |

**별표(＊)**

필수 입력 항목 또는 주의사항을 강조하기 위해 사용하며, 별표 앞뒤로 띄어쓰기를 하지 않아요.

| 구분 | 예시 |
| --- | --- |
| NO | * 5MB 이하의 크기로 첨부해주세요, 모집 안내 * |
| YES | \*5MB 이하의 크기로 첨부해주세요, 모집 안내\* |

## 3. 신조어

**사용자 이해를 저해하지 않는 범위 내에서 제한**

신조어는 타겟 사용자가 일반적으로 이해할 수 있는 경우에만 허용하며, 안내나 에러 메시지 등 정보 전달이 중요한 영역에서는 사용하지 않아요. 그리고 표준어로 충분히 전달 가능한 경우, 신조어 대신 표준어를 사용해주세요.

| 구분 | 예시 |
| --- | --- |
| NO | 아쉽지만 광탈이예요. |
| YES | 아쉽지만 다음 기회에 뵐게요. |

## 4. 외국어/외래어

**대문자·소문자 표기 규칙**

영문표기는 원어의 표기 방식을 따르며, 서비스 내에서 동일한 기준으로 통일해주세요.

- 영문 문장의 첫 글자는 대문자로 시작해주세요.
- 약어는 대문자로 표기해주세요.
- 한글 문장에 포함된 영문은 소문자를 기본으로 해주세요. 단, 약어나 고유명사는 제외예요.
- 제목 작성 시에는 명사형은 모두 대문자로 표기해주세요. 단, 소문자로 표기해야하는 고유명사는 제외해 주세요.

| 구분 | 예시 |
| --- | --- |
| NO | login failed, ppt, pdf, url, ux/ui, 로그인 후 PROFILE을 확인하세요., User profile for makers |
| YES | Login Failed, PPT, PDF, URL, UX/UI, 로그인 후 profile을 확인하세요., User Profile for makers |

**외래어 사용 지양 및 맞춤법**

다만, 맞춤법에 맞지 않더라도 유저에게 더 익숙한 표현이라면 그대로 적어주세요.

| 구분 | 예시 |
| --- | --- |
| NO | 컨텐츠, 메세지, 에러, 재부팅, 체크, 섬네일, ~해 주세요. |
| YES | 콘텐츠, 메시지, 오류, 재시작, 선택, 썸네일, ~해주세요. |

**사용자**

제작자 시점에서 서술할 때는 '유저', 앱 내에서 사용자를 직접 가리킬 때는 '사용자'를 활용해 주세요.

| 구분 | 예시 |
| --- | --- |
| 유저 | 프로젝트 과정이나 후기를 외부에 공유하는 콘텐츠에서 사용 |
| 사용자 | 앱 화면, 안내 문구 등 서비스 내부에서 사용자를 직접 지칭할 때 사용 |

**기타**

서비스 전반에서 자주 사용하는 표현은 아래 기준에 따라 일관되게 작성해 주세요.

| 구분 | 명칭 |
| --- | --- |
| NO | 인터뷰, 푸쉬 알림 |
| YES | 면접, 푸시 알림 |

## 5. 정책

**준말**

- '됐어요'처럼 줄여 쓰지 않고 '되었어요 / 되었습니다'를 사용해요.

**외부 서비스 명은 원문 유지**

- 외부 서비스 명은 원문을 유지하고 줄임말을 지양해주세요.
- 외부 서비스 명의 띄어쓰기 규칙도 원문을 유지해주세요.

**번호 뒤 온점(.) 표기**

- 문장이나 단어 앞에 번호를 매길 때에는 매긴 번호 뒤에 꼭 온점을 찍어주세요.

**요일은 한글로 표기**

- 요일은 한글로 표기하되, 괄호 안에 들어갈 경우에는 줄임말을 허용해요.

**숫자는 n(자연수 형태)으로 표기**

- 숫자는 앞에 0을 붙이지 않고 자연수 형태로 표기해주세요. (특히 문장 및 단어 앞에 번호를 매길 시)
- 임시 데이터를 작성할 때는 "n" 형태를 사용해주세요.

**날짜는 YYYY.MM.DD 형태로 표기**

- 기본적으로 온점을 포함해 'YYYY.MM.DD' 형태로 표기하되, 맥락상 불필요한 날짜 정보는 제거할 수 있어요.
- 날짜 간 범위를 나타낼 때는 물결표(~)를 사용해주세요. (ex. YYYY.MM.DD ~ YYYY.MM.DD)
- 맥락상 한글 표기를 해야할 경우, YYYY년 MM월 DD일로 표기해주세요.

**예시는 ex. 형태로 표기**

- example의 줄임말인 ex와 온점을 사용하고, 온점 뒤에는 띄어쓰기를 해주세요.

**질문과 답변은 Q. / A. 형태로 표기**

- 질문은 Question의 줄임말인 Q와 온점을 사용하고, 답변은 Answer의 줄임말인 A와 온점을 사용하고, 온점 뒤에는 띄어쓰기를 해주세요.

**댓글 작성시간 표기**

- 1분 전까지: 방금 전
- 60분 전까지: n분 전
- 24시간 전까지: n시간 전
- 365일 전까지: n일 전
- 이후: n년 전
